# Система учёта заявок на ремонт мультимедийного оборудования

ФИО: Дудин Семен Дмитриевич  
Группа: ТРИС-2-23

## Описание проекта

Веб-приложение для учёта заявок на ремонт мультимедийного оборудования. Пользователи могут просматривать обращения и создавать заявки с указанием аудитории и описанием неисправности.

## Стек технологий

- Vue 3
- JavaScript
- Vite
- ASP.NET Core (серверная часть, планируется)
- PostgreSQL (база данных, планируется)

## Клиентское приложение

Клиентская часть находится в каталоге `frontend`.

### Требования

- Node.js 22 или совместимая актуальная LTS-версия
- npm

### Установка зависимостей

Из корня репозитория выполните:

```bash
cd frontend
npm install
```

### Запуск в режиме разработки

```bash
npm run dev
```

После запуска откройте адрес, указанный в терминале Vite. Обычно это:

http://localhost:5173/

### Production-сборка

```bash
npm run build
```

Готовые файлы сборки создаются в каталоге `frontend/dist`.

## Реализованные экраны ЛР3

- **Список заявок:** отображение заявок, статусов и статистики.
- **Создание заявки:** форма с проверкой введённых данных.
- **Вход в систему:** демонстрационная форма авторизации.

На текущем этапе данные хранятся в памяти клиентского приложения. Подключение backend, базы данных и настоящей авторизации не реализовано.

## Серверное приложение (ASP.NET Core)

Backend находится в каталоге `backend`.

### Требования
- .NET SDK 10.0 или новее.

### Запуск Backend

Из корня репозитория:

    cd backend
    dotnet restore
    dotnet run

API: http://localhost:5000

Swagger: http://localhost:5000/swagger

### Служебные маршруты

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/health` | Проверка доступности процесса |
| GET | `/info` | Информация о приложении и среде |

`/health` возвращает HTTP 200 и `ok`. Он проверяет только доступность процесса (liveness), а не создание заявок или сохранение данных.

### Ограничения лабораторной работы 7

- Создание заявок пока не реализовано.
- Создание заявок будет реализовано в лабораторной работе 8.
- Данные заявок в последующих этапах будут храниться в памяти и пропадать после перезапуска приложения.
