# Лабораторная работа №12
## Сквозная интеграция веб-приложения

### 1. Цель работы

Проверить сквозную работу веб-приложения для обработки заявок на ремонт мультимедийного оборудования. Выполнить полный сценарий работы диспетчера и техника, проверить взаимодействие клиентской части, серверного API и базы данных PostgreSQL, а также убедиться в сохранении данных после перезапуска сервера.

### 2. Используемые технологии

- Vue 3 — разработка клиентской части приложения.
- JavaScript — логика frontend.
- Vite — запуск клиентского приложения.
- ASP.NET Core 10 — серверная часть и REST API.
- Entity Framework Core 10 — работа с базой данных.
- PostgreSQL 16 — хранение данных.
- Cookie Authentication — аутентификация пользователей.
- DevTools браузера — проверка HTTP-запросов и ответов.

### 3. Проверка авторизации

Выполнен вход в приложение под учетной записью диспетчера. После авторизации проверена доступность функций создания заявок и назначения исполнителей.

Затем выполнен вход под учетной записью техника. Проверена доступность заявок, назначенных данному пользователю, и возможность изменения статуса заявки.

### 4. Создание и обработка заявки

Через пользовательский интерфейс была создана заявка на ремонт мультимедийного оборудования.

| Параметр | Значение |
|---|---|
| ID | 6 |
| Номер | 1004 |
| Название | Проектор |
| Описание | Не показывает изображение |
| Аудитория | 210 |

| Исполнитель | 7 |
| Начальный статус | New |

Диспетчер назначил заявку технику с ID 7. Назначение было успешно обработано сервером.

После входа под учетной записью техника статус заявки изменён с `New` на `InProgress`. API вернул обновлённые данные заявки.

### 5. Проверка взаимодействия компонентов

Проверено взаимодействие между интерфейсом, сервером и базой данных.

- Создание заявки через пользовательский интерфейс.
- Передача данных на сервер через API.
- Назначение исполнителя диспетчером.
- Изменение статуса авторизованным техником.
- Получение заявки через API.
- Проверка данных в DevTools браузера, вкладка Network, Fetch/XHR, Response.
- Сопоставление ID заявки в интерфейсе, ответе API и базе данных.

### 6. Проверка PostgreSQL

Выполнен SQL-запрос для проверки созданной заявки:

```sql
SELECT id, number, title, status, classroom_id, assignee_user_id
FROM repair_requests
WHERE id = 6;
```

В результате получена запись:

| ID | Номер | Название | Статус | Аудитория | Исполнитель |
|---|---|---|---|---|
| 6 | 1004 | Проектор | InProgress | 210 | 7 |

Полученные данные соответствуют данным, возвращаемым сервером API.

### 7. Проверка сохранения данных после перезапуска

Для проверки сохранения данных сервер API был остановлен и запущен повторно.

После перезапуска выполнен GET-запрос для получения заявки с ID 6. Сервер вернул ранее созданную заявку с тем же номером, названием, статусом, аудиторией и назначенным исполнителем.

Таким образом, подтверждено сохранение данных в PostgreSQL после перезапуска серверного приложения.
