## 3. Создание структуры базы данных

Подготовлен файл `db/schema.sql`, содержащий описание трёх таблиц.

### 3.1. Таблица classrooms

Справочник аудиторий содержит:
- `id` — первичный ключ;
- `name` — название аудитории.

### 3.2. Таблица users

Таблица пользователей содержит:
- `id` — первичный ключ;
- `login` — уникальный логин;
- `name` — имя пользователя;
- `role` — роль пользователя.

Для поля `role` установлено ограничение CHECK. Допустимые роли: `Teacher`, `Dispatcher`, `Technician`.

### 3.3. Таблица repair_requests

Основная таблица заявок содержит:
- `id` — первичный ключ;
- `number` — уникальный номер заявки;
- `title` — заголовок;
- `description` — описание неисправности;
- `status` — статус заявки;
- `classroom_id` — внешний ключ на аудиторию;
- `created_by_user_id` — внешний ключ на автора заявки;
- `assignee_user_id` — внешний ключ на исполнителя, допускающий NULL;
- `created_at` — дата и время создания заявки.

Для поля `status` установлено ограничение CHECK. Разрешены значения `New`, `InProgress`, `Closed`, `Cancelled`.

### 3.4. Индексы

Созданы индексы:
- `idx_repair_requests_status` — для фильтрации по статусу;
- `idx_repair_requests_classroom` — для поиска заявок по аудитории;
- `idx_repair_requests_created_at` — для сортировки по дате создания.

## 4. Заполнение тестовыми данными

В файле `db/seed.sql` подготовлены тестовые записи.

После выполнения скрипта получено:

| Таблица | Количество записей |
|---|---:|
| classrooms | 3 |

Для заявок использованы все четыре допустимых статуса. Для некоторых заявок исполнитель не назначен, поэтому поле `assignee_user_id` содержит NULL.

## 5. Выполнение SQL-запросов

Запросы сохранены в файле `db/queries.sql`.

### 5.1. Фильтрация и сортировка

Выполнен запрос для получения заявок со статусом `New`. Результаты отсортированы по дате создания в порядке убывания.

Получена одна запись — заявка №1002 «Не работает микрофон».

### 5.2. Объединение таблиц JOIN

С помощью `JOIN` объединены таблицы `repair_requests`, `classrooms` и `users`.

Для получения имени исполнителя использован `LEFT JOIN`, поскольку исполнитель может отсутствовать.

Запрос успешно вернул все четыре заявки с названиями аудиторий, именами авторов и назначенных исполнителей.

### 5.3. Группировка GROUP BY

Выполнена группировка заявок по статусу с использованием функции `COUNT(*)`.

Результат:

| Статус | Количество |
|---|---:|
| Cancelled | 1 |
| Closed | 1 |
| InProgress | 1 |
| New | 1 |

## 6. Проверка ограничений целостности

Выполнена попытка добавить заявку с недопустимым статусом `Done`.

PostgreSQL отклонил операцию и вывел ошибку нарушения ограничения:

`violates check constraint "repair_requests_status_check"`.

Это подтверждает корректную работу ограничения CHECK. Некорректная запись в таблицу не добавлена.
